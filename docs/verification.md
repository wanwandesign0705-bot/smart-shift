# 見た目と動きの確認（作業1・2）

v2.3（claude.ai のアーティファクト版）と、この Vite 版を同じ操作で動かし、画面のスクリーンショットを1ピクセル単位で比べました。

## 結果（2026-11-22）

| 項目 | 結果 |
|---|---|
| 画面の比較（32画面 × パソコン・ライト／スマホ・ダーク） | 64画面すべて一致 |
| ブラウザに保存された中身（店舗データ・申請・端末の設定） | 2パターンとも一致 |
| 画面上のエラー | どちらの版も0件 |
| Excel出力（シフト表・有給管理簿） | ファイルができ、中身と「参考値」の注記を確認（Vite版のみ。v2.3 は claude.ai の中でしか保存できないため） |

比べた画面：スタッフ画面（名前選び、マイシフト、全体、申請、申請後、社内連絡）、ロック画面（パスワード違いを含む）、規約への同意、管理者の7タブ、セルの編集、申請の承認、業種テンプレートの切り替え、年払い表示、予約管理、アップデート情報、規約3ページ、翌月への移動、自動生成、公開、再読み込み後（スタッフ画面・有給管理）。

## 変わったところ（意図した違い）

- **保存先**：v2.3 は claude.ai にサインインしているときは claude.ai の共有DBに保存していました。Vite 版はブラウザ内だけに保存します（Supabase は作業4から）。そのため画面左上の表示は常に「この端末に保存」です
- **Excel出力**：claude.ai のダウンロード機能の代わりに、ブラウザ標準のダウンロードを使います。ExcelJS は CDN からではなく npm から、ボタンを押したときに読み込みます
- **起動**：データを読み終わってから描くようにしました（Supabase に替えたときに必要）。表示までの差は目に見えません

## 比べるときの条件

- 両方の時計を同じ時刻に固定（申請日時の「秒」で差が出るため）
- 外部のフォント・CDN は両方とも読み込まない（同じ代わりのフォントで描かれる）
- 撮る前にマウスを画面の外に出し、アニメーションが終わるまで待つ

同じ条件でも、実行のたびにどこか1画面で表の固定列の境目が1列だけ違うことがありました（違う画面は毎回変わり、目では分かりません）。ブラウザの描画の揺れで、アプリの違いではありません。

## 自分で確かめるとき

```bash
npm run build
npx vite preview --port 4173 --strictPort
```

別のターミナルで：

```bash
npm run compare
```

画像は `compare-output/` に出ます（`v23-…` と `vite-…` が同じ画面の組です）。Playwright が入っている環境で動きます。
