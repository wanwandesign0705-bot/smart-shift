# 店長の登録とログイン（作業3）

## できること

`.env` に Supabase の値があるとき、画面右上の「管理者メニュー」は、パスワードのロック画面の代わりに店長のログイン画面になります。

```
ログイン ──→ 規約への同意 ──→ お店の作成 ──→ 管理画面
   │            （初回だけ）      （初回だけ）
   └ 新しく登録する → 確認メールを送りました → メールのリンクを押す → 規約への同意 …
   └ パスワードを忘れたとき → 再設定のメール → リンクを押す → 新しいパスワードを決める
```

- **新規登録**：メールアドレスとパスワード（8文字以上、英字と数字をまぜる）。確認メールのリンクを押すと、続きの画面に戻ってきます
- **規約への同意**：利用規約とプライバシーポリシーの両方にチェックが必要です。版（`src/config/legal.js` の `LEGAL.ver`）と日時が、データベースの `consents` に残ります。版を上げると、次のログインで同意し直してもらいます
- **お店の作成**：お店の名前、業種、会社全体の従業員数を選びます。データベースの `create_store` で作り、2ヶ月の無料トライアルが自動で始まります。続けて、業種テンプレートのシフト区分・必要人数・巡回パターン（とサンプルのスタッフ・時給）を入れます
- **ロボット対策**：登録・ログイン・パスワード再設定には、Cloudflare Turnstile の確認が必要です
- **ログアウト**：管理画面の右上から

`.env` に値がないときは、これまでどおりパスワード（初期値 `admin`）のロック画面で動きます。

## まだできないこと（次の作業で）

- 管理画面のシフト・名簿・設定は、まだ**この端末に保存**しています。Supabase に入れたテンプレートは、作業4で管理画面とつなぎます
- スタッフの招待リンク（作業5）
- 確認メールの文面は、Supabase の初期のまま（英語）です。日本語にするのは公開の前（作業10）に行います

本物の Supabase には、この環境から次のことを確かめました。

- ログイン前の人は、店舗と時給の表を読めない（拒否される）。お知らせは読める
- メール登録と匿名ログイン（招待リンク用）がオンで、メールの確認もオン
- ロボット対策の確認がない登録は、Supabase が断る

本物のメールを使った登録は、この環境からはできません（確認メールを受け取れず、ロボット対策も通れないため）。公開したあとに、店長のメールアドレスで1回通して確かめます。

### テスト中に見つけて直した不具合

- 「登録する」を押した瞬間に画面を描き直していたため、ロボット対策の確認結果が消えて、空のまま送っていた。本物の Supabase では必ず断られるところだった。押した時点の結果を取っておいて送るように直した
